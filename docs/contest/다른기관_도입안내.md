# 다른 기관 도입 안내 — 우리 기관 내규로 규정 제·개정 에이전트 쓰기

이 안내서는 다른 공공기관이나 지자체가 **프로그램 코드를 고치지 않고** 자기 내규로 에이전트를 쓰는 순서를 정리한 것이다.

- 측정 환경: 이 저장소의 시험 환경(리눅스, Python 3.13 새 가상환경)에서 2026-11-04에 쟀다.
- 시험 자료: 가상 기관 예시 `samples/public_org/`(실제 기관 아님, 내규 7건)
- 사람이 문서를 고치는 시간은 재지 않았다. 대신 고칠 항목 수를 적었다.

| 단계 | 할 일 | 측정 시간 |
|---|---|---|
| 1. 설치 | 의존성 설치 | 9.5초(인터넷 연결 환경) |
| 2. 내규 들여오기 | 원문 폴더 → 명령 한 줄 | 0.07초 (7건) |
| 3. 기관 설정 | `org_config.json` 고치기 → 점검 도구 | 기본 항목 5개, 옛 명칭, 근거 조항. 점검 0.26초 |
| 4. 실행 | 환경변수 3개 지정 후 서버 실행 | 0.44초 |
| 5. 첫 개정 | 에이전트에 한 문장 요청 | 0.3초 (AI 키 없이) |

---

## 1. 설치

준비물은 다음과 같다.
- Python 3.12 이상(시험: 3.12와 3.13)
- 이 저장소

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

**인터넷이 막힌 업무망:** 인터넷 되는 PC에서 패키지를 받아 반입한다.
- 받기: `pip download -r requirements.txt -d wheels`
- 업무망에서 설치: `pip install --no-index --find-links wheels -r requirements.txt`
- 필요한 패키지는 8개다(flask, numpy, pypdf 등).

## 2. 내규 들여오기

1. 내규 원문을 한 폴더에 모은다. 파일명이 그대로 규정명이 된다.
   - 예: `여비규정(2024년도 3월 일부개정).hwpx` — 괄호 안은 개정 정보로 쓰인다.
2. 아래 명령을 실행한다. `--reset`은 기존 내규 데이터를 지우고 새로 만들 때만 쓴다.

```bash
export REG_DIR=/srv/regagent/regulations REG_MANIFEST=/srv/regagent/manifest.json
python scripts/import_regulations.py <원문 폴더> --reset
```

Windows PowerShell에서는 다음과 같이 한다.

```powershell
$env:REG_DIR="C:\regagent\regulations"; $env:REG_MANIFEST="C:\regagent\manifest.json"
python scripts\import_regulations.py <원문 폴더> --reset
```

- `REG_DIR`을 지정하지 않으면 `--reset`은 저장소의 기본 내규를 지우지 않고 멈춘다. 그래도 기본 데이터를 바꾸려면 `--force`를 함께 준다.
- `--reset`은 기존 폴더를 지우지 않고 옆에 `.backup-날짜시각` 폴더로 옮겨 둔다.

| 형식 | 처리 |
|---|---|
| `.hwpx` (권장) | 조문·별표 단위로 변환 |
| `.hwp` (구형 한글) | 본문 글자를 뽑아 조문 단위로 변환. 실패하면 “HWPX로 저장해 올리세요” 경고 |
| `.docx`, `.txt`, `.md`, `.html` | 조문 단위로 변환 |
| `.pdf` | 원본을 보여 준다. 글자 층이 있으면 검색·개정에 쓴다 |

- 들여온 뒤에는 화면의 **내규 등록**(`/upload`)으로 한 건씩 최신본을 올려 유지할 수 있다.
- 등록 권한은 `REG_UPLOAD_TOKEN`으로 보호한다.

## 3. 기관 설정 (`org_config.json`)

`samples/public_org/org_config.json`을 복사해서 고친다.

| 꼭 고칠 항목 | 뜻 | 예 |
|---|---|---|
| `org_name` · `org_short` | 기관명·약칭. 초안 제1조와 문서에 들어간다 | 가상행정진흥원 · 진흥원 |
| `head` · `deputy` | 기관장·부기관장 호칭. 결재선·위원장 문구에 쓰인다 | 원장 · 부원장 (또는 사장 · 부사장) |
| `email_domain` | 직원 메일 도메인 | example.go.kr |
| `stale_terms` · `stale_words` | 옛 명칭 → 새 명칭. 건강검진에서 남은 곳을 짚는다 | [["가상행정연구원","가상행정진흥원"]] |
| `alio.apba_id` | 알리오 기관 코드. 다른 기관 사례 조사에서 우리 기관을 뺀다(선택) | |

### 근거 조항을 우리 규칙에 맞추기 — 가장 흔한 실수

다른 기관 프로필을 베끼면 아래 항목이 **남의 「내규관리규칙」 조 번호**를 그대로 가리킨다.
- `lint_refs` (점검 근거)
- `review_criteria[].ref` (심의 기준 근거)
- `procedure` 질문·단계의 `ref` (절차 근거)

우리 규칙의 조 번호로 고치거나, 모르면 빈칸(`""`)으로 둔다. 빈칸이면 화면과 문서에 근거를 적지 않는다(빈 괄호도 생기지 않는다).

### 점검 도구로 확인

```bash
ORG_CONFIG=org_config.json python scripts/check_org_config.py
```

점검 도구는 아래를 확인한다.
- 기본 항목이 비었거나 기본값인지
- 근거 규칙(`rules_name`)이 들여온 내규에 있는지
- 근거 조항이 그 규칙에 실제로 있는지
- 기관명이 내규 글에 나오는지(남의 프로필을 그대로 쓰는 실수)
- 옛 명칭이 몇 곳에 남았는지

시험 결과는 다음과 같다.
- **농진원 프로필을 그대로 둔 채 가상 기관 내규를 쓴 경우**
  - “근거 조항 36/37개가 「내규관리규칙」에 없습니다”라며 해당 항목을 하나하나 짚었다.
  - “기관명·약칭이 내규 어디에도 없습니다”도 짚었다.
- **가상 기관에 맞게 고친 뒤:** “근거 조항 15개 모두 있음, 오류 0”.
- **운영 중인 농진원 프로필:** 근거 조항 37개가 모두 실제 조문에 있다. 옛 명칭 “실용화재단”이 1곳 남은 것도 찾았다.

## 4. 실행

```bash
ORG_CONFIG=org_config.json REG_DIR=... REG_MANIFEST=... python run_local.py   # http://localhost:5100
```

- 사내 서버 한 대에서 돌린다.
- 화면 왼쪽 아래에 기관명과 등록 내규 수가 나오면 정상이다.

## 5. 첫 개정 (AI 키 없이)

에이전트 화면에 한 문장으로 요청한다.

| 요청 예 | 결과 |
|---|---|
| “여비규정 제7조의 일비를 3만원으로 올려줘” | 수치 반영 → 인용 영향 → 점검 → 개정문 왕복 검증 → 검토 보고서·문서 7종 |
| “여비규정에서 여비를 출장비로 바꿔줘” | 내규 전체에서 낱말을 바꾸고 조사도 맞춘다 |
| “복무규정 제6조를 삭제해줘” | 이 조를 인용하는 같은 내규·다른 내규 조문을 찾아 알린다 |

가상 기관에서 위 요청은 모두 0.1~0.3초에 끝났다(`docs/contest/다른기관_도입시험.md`).

## 6. 상위법 개정 감시 (자동 알림)

우리 내규가 인용하는 법령·행정규칙이 **지난번 확인 이후 새로 공포됐거나 시행됐는지** 찾아서, 인용하는 내규와 함께 알린다.

**화면에서 쓸 때**
- 건강검진의 “상위법·행정규칙 최신성 확인”을 한 번 하면 그 결과가 기준으로 저장된다.
- 이후 화면을 열 때 하루 한 번 자동으로 다시 확인한다. 끌 수 있다.
- 바뀐 것이 있으면 건강검진 메뉴에 숫자가 뜬다.
- “상위법 변경 알림” 카드에서 **영향 조문 찾기 → 개정**으로 바로 이어진다.

**사내 서버에서 매일 돌릴 때** — 메신저로 알림을 받는다.

```bash
# 매일 08:10 (리눅스 cron). 윈도는 작업 스케줄러에 같은 명령을 등록
10 8 * * *  cd /srv/regagent && WATCH_WEBHOOK=<사내 메신저 수신 웹훅 주소> .venv/bin/python scripts/watch_laws.py
```

- **처음 실행:** 기준만 저장한다(`law_watch_state.json`, 위치는 `WATCH_STATE`로 바꿀 수 있다).
- **그다음부터:** 바뀐 것이 있을 때만 웹훅으로 `{"text": 보고}`를 보낸다.
- **법제처 접속이 모두 실패하면:** 기준은 그대로 두고 종료 코드 3으로 끝난다. 망 차단 여부를 확인한다.

## 7. 선택 사항

| 항목 | 하는 일 | 없을 때 |
|---|---|---|
| AI 키(화면의 AI 설정) | 자유로운 개정 의도를 수정안으로 작성, AI 검토의견 | 수치·낱말·조 삭제·이동은 규칙으로 처리, 나머지는 직접 고침 |
| 의미 검색 색인(`scripts/build_embeddings.py`) | 뜻이 비슷한 조문 찾기 | 낱말 검색으로 동작 |
| 법제처·알리오 접속 | 상위법·다른 기관 사례 조사 | 해당 조사만 빠지고 나머지는 그대로 동작(막힌 망의 화면 표시는 11/7 업무망 점검에서 다룸) |

자동 시험은 `tests/test_public_org.py`에 있다. 가상 기관 원문 들여오기, 엔진 동작, 점검 도구를 CI에서 매번 확인한다.
