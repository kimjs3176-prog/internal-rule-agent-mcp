# 결선 5분 시연 대본 — 규정 제·개정 에이전트

- **시연 조건:** AI 키 없이, 외부망(법제처·알리오) 없이. 업무망에서 가장 불리한 조건이라 결선장 망 상태와 상관없이 끊기지 않는다.
- **시연 데이터:** 한국농업기술진흥원 실제 내규 126건
- **대기 시간:** 각 장면의 대기 시간은 2026-11-06 답사에서 1920×1080 화면으로 잰 값이다. 화면 변화는 모두 2초 안에 끝난다.

## 사전 준비 (발표 30분 전)

| 확인 | 방법 |
|---|---|
| 서버 실행 | `python run_local.py` → 브라우저에서 `http://localhost:5100` |
| 깨끗한 화면 | 브라우저 **새 시크릿 창**으로 연다. 지난 연습의 작업 내용이 남지 않게 하기 위함 |
| 해상도 | 프로젝터 1920×1080(또는 1280×720). 글자가 작으면 브라우저 확대 110~125% |
| 첫 화면 | 「에이전트에게 맡기기」, 왼쪽 아래 “한국농업기술진흥원 · 등록 내규 126건” |
| 비상용 | 리허설 화면 캡처(11/6 오후 리허설 스크립트가 만든다)를 발표 자료 맨 뒤에 붙여 둔다 |

## 시간표

| 시간 | 장면 | 핵심 메시지 |
|---|---|---|
| 0:00–0:40 | ① 문제 제기 — 건강검진 | 사람이 하면 틀린다. 지금 내규에도 남아 있다 |
| 0:40–1:50 | ② 한 문장 요청 → 자료조사·보고서 | 한 문장이면 끝까지 간다(0.5초) |
| 1:50–2:50 | ③ 대비표·점검·개정문 검증 → 문서 받기 | 틀리지 않게 확인까지 한다 |
| 2:50–3:50 | ④ 모든 내규 일괄 정비 | 하루 일을 0.1초에 |
| 3:50–4:30 | ⑤ 조 삭제 — 사람이 놓치는 인용 | 놓치는 곳을 먼저 짚는다 |
| 4:30–5:00 | ⑥ 숫자와 확산 | 실측 성과, 다른 기관도 바로 |

## ① 문제 제기 — 0:00~0:40

**화면:** 왼쪽 메뉴에서 **건강검진** 클릭 → 1.5초 뒤 진단 결과

> 규정을 고치는 일은 생각보다 손이 많이 갑니다. 고칠 곳을 찾고, 그 조를 인용하는 다른 조와 다른 규정까지 확인하고, 개정문과 신구조문대비표, 이유서, 심의 서식까지 씁니다. 그러다 보니 사람이 하면 틀립니다.
>
> 저희 기관 내규 126건 전체를 1.5초 만에 진단한 화면입니다. **인용·명칭·번호 문제가 20곳**, **오류가 있는 내규가 4건** 나왔습니다. 제16조까지밖에 없는 규칙이 제17조를 인용하고, ②항이 두 번 나오는 조문도 있습니다. 이미 확정된 내규에 남아 있는 실수입니다.

**화면에 보이는 값(실측):** 평균 건강 점수 94.7 · 문제가 발견된 내규 82건 · 인용·명칭·번호 문제 20곳 · 오류가 있는 내규 4건

## ② 한 문장 요청 — 0:40~1:50

**화면:** 왼쪽 메뉴 **에이전트** → 입력 칸에 직접 입력 → **에이전트 실행**
- 입력할 문장: **여비규정 제15조의 일비를 3만원으로 올려줘**
- 직접 타이핑하는 것이 인상적이다. 시간이 빠듯하면 아래 예시 칸 “개정 — 여비규정 제15조의…”를 눌러 채운다.

**대기:** 0.5초 → “「여비규정」 자료조사·개정안·검토 보고서가 준비됐습니다” 아래로 14단계 작업 내역

> 담당자가 하는 말 그대로 한 문장만 넣었습니다. 0.5초 만에 에이전트가 14단계를 끝까지 처리했습니다.
> - 제15조를 불러오고, 일비가 실제로 적힌 **별표 2 표의 일비 칸만** 25,000원에서 30,000원으로 바꿨습니다.
> - 이 조를 인용하는 곳 3건을 확인했습니다.
> - 형식 점검과 심의 사전검토를 하고, 절차를 잡고, 문서 세트까지 준비했습니다.

**클릭:** **검토 보고서 열기**

> 상급자에게 올릴 검토 보고서 초안도 함께 나옵니다.
> - **현황:** “일비 25,000원 → 30,000원으로 조정 필요”
> - **자료조사:** 같은 업무의 「여비업무 처리지침」과 인용 영향
> - **검토 의견:** 형식 점검과 개정문 검증 결과

## ③ 대비표·점검·개정문 검증 → 문서 받기 — 1:50~2:50

**화면:** 위쪽 단계 표시에서 **확인·검토** → **모두 점검하기**

**대기:** 1.1초 → 칩 표시: 대비표 1행 · 인용 영향 5곳 · 형식 점검 오류 없음 · 개정문 검증 **개정문 일치** · 사전검토

> 신구조문대비표에서 바뀐 곳이 색으로 보입니다(25,000 → 30,000).
>
> 가장 중요한 것은 **개정문 검증**입니다. 개정문을 현행 규정에 다시 적용해 보고, 결과가 개정안과 글자 하나까지 같은지 확인합니다. 저희 내규 125건 전체에 조 신설·삭제·항 끼워 넣기 같은 수정을 619번 해 봤는데, 619번 모두 일치했습니다.

**클릭:** 단계 표시 **문서 받기** → 문서 탭 11종(검토 보고서·심의안건서·개정문·이유서·신구조문대비표·사전예고문·의견수렴 공고 …) → 아래 **한글(hwpx)**

**대기:** 0.06초 → 한글 파일 저장

> 심의에 올릴 문서를 한글 파일 하나로 받습니다. 개정문, 대비표, 이유서, 의견서까지 들어 있습니다.

## ④ 모든 내규 일괄 정비 — 2:50~3:50

**화면:** **에이전트** → 입력 → **에이전트 실행**
- 입력할 문장: **모든 내규에서 기획운영본부를 경영기획본부로 바꿔줘**
- 예시 칸 “일괄 정비 — 기획운영본부를 경영기획본부로…”를 눌러도 된다.

**대기:** 0.09초 → “24개 내규, 29곳” → **일괄 정비 결과 열기**

> 조직 개편으로 부서 이름이 바뀌면, 사람은 내규 126건을 하나씩 열어 찾아야 합니다. 저희 산정으로 꼬박 하루, 8.8시간 일입니다.
>
> 에이전트는 0.1초 만에 24개 내규에서 29곳을 찾았습니다. 내규별 개정문, “다른 내규의 개정” 부칙, 통합 신구조문대비표까지 만들었습니다.
>
> 이름이 바뀌면 뒤에 붙는 조사도 맞춥니다. 예를 들어 “윤리감사실을 둔다”를 바꾸면 “감사부를 둔다”가 됩니다.

## ⑤ 조 삭제 — 사람이 놓치는 인용 — 3:50~4:30

**화면:** **에이전트** → 입력: **여비규정 제20조를 삭제해줘** → **에이전트 실행**

**주의:** “개정 탭의 진행 중인 작업을 지우고 에이전트 결과로 바꿀까요?” 대화상자가 뜬다(②의 작업이 남아 있어서). **확인**을 누른다.

**대기:** 0.35초 → 작업 내역
- 조문 삭제: “제20조 삭제 · 인용하는 제24조 함께 담음”
- 조문 점검: “제24조에서 삭제된 제20조를 인용합니다”

> 조를 지울 때 가장 많이 놓치는 것이, 그 조를 인용하던 다른 조입니다. 에이전트는 제20조를 지우면서 이 조를 인용하는 제24조를 찾아 같이 고치도록 담았습니다. 고치지 않으면 점검에서 오류로 막습니다.

## ⑥ 숫자와 확산 — 4:30~5:00

**화면:** 발표 자료 마지막 장(숫자 요약). 시연 화면은 그대로 둔다.

> 정리하겠습니다. 모두 저희 실제 내규로, AI 없이 잰 숫자입니다.
> - 사람이 흔히 내는 오류 10종을 1,243번 심었는데 **1,243번 모두 잡았습니다.**
> - 개정문 검증은 **619번 모두 일치**했습니다.
>
> 다른 기관도 바로 쓸 수 있습니다. 가상 기관 내규 7건을 들여오는 데 0.06초가 걸렸고, 코드는 한 줄도 고치지 않았습니다. 상위법이 바뀌면 이를 인용한 내규를 자동으로 찾아 알려 줍니다.
>
> 규정 담당자가 틀리기 쉬운 일을 먼저 막는 에이전트를 범정부 공공재로 내놓겠습니다. 감사합니다.

| “법제처·알리오 연결은?”이라는 질문 | “망이 열린 곳에서는 상위법 최신성과 다른 기관 사례를 함께 조사합니다. 지금은 연결 없이 시연했습니다.” |
| 다른 내규로 해 보자는 요청 | 에이전트에 “복무규정 제27조의 연차 일수를 20일로 해줘”를 넣는다. 값이 여러 곳(1일·15일)에 있어 **추측하지 않고 위치를 알리는** 안전장치를 보여 준다 |
