# 전체 기능 점검 결과와 개선점 (2026-11-07)

## 1. 점검 방법

- **범위:** 7개 영역을 나눠 점검했다. 그 뒤 아무도 시험하지 않은 기능을 골라 1개 영역을 더 점검했다.
  - 에이전트(한 문장 지시)
  - 개정 화면
  - 제정 화면·절차·문서 세트
  - 건강검진·상위법·충돌 점검
  - 찾아보기·자문·용어·조직·일괄 정비
  - 공통 사용성
  - API 견고성·보안·MCP·다른 기관 도입
- **방법:** 영역마다 내규 복사본으로 서버를 따로 띄웠다. 그리고 브라우저(Playwright)와 API로 실제로 써 봤다. 저장소 원본은 건드리지 않았다.
- **검증:** 영역마다 다른 점검자가 지적을 하나씩 다시 재현했고, 기본 태도는 반박이었다. 다음에 해당하면 걸렀다.
  - 재현되지 않는 것
  - 의도된 동작
  - 환경 제약 탓인 것(AI 키·법제처 LAW_OC·외부망 없음)
  - 이미 「보완점검.md」에 있는 것
- **환경:** AI 키 없음(규칙 모드), LAW_OC 없음, 외부망 차단.
  - AI 경로는 가짜 OpenAI 호환 서버로 확인했다.

## 4. 고치면 좋은 것 — 중간 48건(주제별)

### 4-1. 에이전트 요청 해석
- **AG-2:** 없는 내규명(“우주항공규정 제3조 삭제”)이나 내규명 없는 조 삭제 → 유사 검색 1위인 엉뚱한 내규의 조를 지우고 녹색 완료로 끝난다.
  - 고칠 방향: 추정으로 고른 대상은 멈추고 후보 3개를 보여 확인받는다.
- **AG-4:** “14일에서 30일로”, “N일을 M일로” 같은 흔한 수치 표현을 못 알아듣는다(AG-1과 같은 함수).
- **AG-5:** “제8조의 14일”을 가지조(제8조의14)로 읽는다. 소유격 ‘의’ 뒤에 단위가 오면 가지번호가 아니다.
- **AG-6:** 한 요청에 지시가 둘 이상이면 첫 번째만 반영하고 나머지를 말없이 버린다.
  - 고칠 방향: 지시마다 나눠 적용하고, 못 한 것은 따로 보인다.
- **AG-7:** 조 신설·조 이동 요청을 처리하지 못한다. 신설 요청에 “제29조의2는 없어 가까운 조문을 골랐습니다”라고 거꾸로 안내한다. 구동안내서는 “AI 없이 조 이동·신설”이라고 적었다.
- **AG-8:** 화면 기본 예시 “출장 숙박비 상한을 실비 기준으로 …”가 「공무국외출장 관리규칙」을 대상으로 고른다. 예시 문장에 내규명을 넣는 것이 가장 빠른 대책이다.
- **AG-9:** 수치를 못 찾으면 활용형 낱말(“숙박하”, “저축하여”)로 다시 요청하라고 제안해 막다른 길이 된다.
- **AG-13:** 조 삭제 뒤 ‘삭제된 조 인용’ 오류가 남아도 결론은 “점검까지 마쳤습니다”이고, 주 단추가 문서 받기로 간다.

### 4-2. 개정 화면 정확성
- **AMD-3:** 조 번호를 옮긴 개정에서 ‘이번 개정으로 생긴 오류’ 거르기에 옮긴 번호가 빠진다.
- **AMD-4:** ‘전부개정으로 쓰기’와 조 삭제를 함께 쓰면 개정문 검증이 거짓 불일치를 낸다(일부만 맞음).
- **AMD-5:** 빈 신설 조문이 모든 점검을 통과하고 개정문에 ‘제15조의2()’로 나온다.
- **AMD-6:** 별표·서식만 고친 개정은 인용 영향이 실행되지 않는다.
- **AMD-7:** 별표 표가 한 칸씩 줄로 풀려 대비표와 개정문 별지에서 어느 열이 바뀌었는지 알기 어렵다.
- **AMD-8:** 고치기 단계에 되돌리기가 없다.
- **GAP-2:** 「직제규정」 제3조, 제4조, 제6조처럼 나열한 인용은 두 번째 조부터 인용 영향에 잡히지 않는다.
- **GAP-3:** 부칙에 ‘다른 내규의 개정’이 없는데도 안건서·이유서가 “부칙으로 함께 정비”라고 적는다.
- **HEALTH-V1(HLT-8):** 부칙 속 ‘〔별표1〕’를 별표로 잘못 나눠 별표 id가 겹친다. 그래서 진짜 별표 1을 골라도 부칙 조각이 수정안에 들어간다(14개 내규).
- **HLT-5:** 건강검진의 별표 옛 명칭에서 ‘개정 작업’을 누르면 빈 개정 화면과 ‘제0조’ 의도가 넘어간다.

### 4-3. 제정·문서 세트
- **ENA-3:** 제정 검토 보고서의 ‘자료조사 결과’가 늘 비어 있다.
- **ENA-4·ENA-7:** 절차의 내규 단계가 제정 종류와 연결되지 않는다. 개정 작업이 남아 있으면 절차 안내·추진계획표·작업 실적이 그 개정 건을 가리킨다.

### 11/8 오전 · 1차 수정의 독립 검토(회귀 20건 반영)
1차 수정 diff를 검토자 2명이 따로 봤다. 고치기 전 코드와 같은 입력으로 비교해, 수정이 새로 만든 결함 20건을 재현했다. 모두 고쳤다.
- **수치 해석**
  - 적은 말(“일비”)이 없는 조의 같은 값은 바꾸지 않는다.
  - 한 조 안에 같은 현행 값이 여럿이면 요청문의 앞 구절(“4시간 미만”)로 가린다. 가릴 수 없으면 바꾸지 않는다.
  - “근무 시간을 35시간으로” 꼴을 다시 인식한다.
  - 열쇠말 조사 떼기가 “연차휴가”·“병가”를 자르지 않는다.
  - 카드 이유 칸과 “2만5천원” 안내 표기를 고쳤다.
- **요청문 조 번호:** “제6조의3 일반사택”·“제4조의2 시간외근무”처럼 단위 글자로 시작하는 낱말이 뒤따라도 가지조로 읽는다.
- **인용 판정(화면·서버)**
  - “규정 제25조의 이행관리책임자는 제30조제3항”의 제30조는 같은 내규로 본다(“의 ○○” 뒤 접속어가 있어야 이어짐).
  - “이 지침 제6조 … 및 제12조”는 같은 내규로 본다. “직원이 규정 제35조”의 ‘이’는 조사로 본다.
  - 126개 내규 전체를 고치기 전과 비교해, 남은 차이 17곳이 모두 개선임을 확인했다(다른 법률·내규의 나열 인용을 더는 바꾸지 않음).

  - 등록 내규명·제N조가 실제로 있을 때만 개정으로 본다(“전 규정에서 …”·“재정관리팀 → …”은 일괄 정비).

  - intent를 고쳐 쓸 때 따옴표가 겹치지 않는다.
- **자문**
  - 한 글자 어미는 “어간+하/되” 낱말이 원문에 있을 때만 뗀다(결재권한·신청기한·출입제한 유지).

### 11/8 오전 · 재검토(8건) 반영 — 현행 값 수치 지시를 한 원칙으로 다시 짰다
재검토자가 고치기 전·1차·2차 코드를 같은 입력으로 비교했다. 입력은 수치 요청 91건, 화살표 59건, 자문 57건, 원문에서 자동으로 만든 현행 값 요청 1,006건이다.
- **현행 값 지시(`raVqOldApply`)**
  - 조를 적었으면 그 조에서만 찾는다.
  - 조를 적지 않았으면 적은 말이 그 문장이나 조 제목에 있는 곳만 후보로 둔다. 띄어쓴 낱말은 사이에 네 글자까지 끼어도 인정한다(연차휴가 ↔ 연차유급휴가). 열쇠말이 내규명이면 무엇인지 적지 않은 것으로 본다.
  - 후보가 여럿이면 요청문의 다른 말이 값 앞뒤 구절·조 제목에 가장 많은 한 곳만 바꾼다. 가릴 수 없으면 바꾸지 않고 후보를 알린다.
  - 무엇인지도 조도 적지 않았으면 한 곳뿐이어도 요청문의 말이 맞을 때만 바꾼다.
  - 에이전트가 유사 검색으로 고른 조에 매이지 않는다.
  - 조 제목으로 고른 경우는 안내에 밝힌다.
- **화살표·범위어**
  - “복무규정 전반”·“개정 전 규정”은 범위어가 아니다.
  - 쉼표·닫는 괄호 뒤 화살표를 인식하고, 목록 번호(1)·1.)는 빼고 읽는다.
  - 내규명이 개정 사유로 붙은 조직명 변경은 일괄 정비로 처리한다.
  - 숫자·날짜로 바꾸는 요청은 일괄 정비가 아니다.
  - intent 조사(를/로)를 고쳤다.
- **자문**
  - “포함되나요/해당되나요”는 묻는 낱말이 한 문장에 함께 나와야 단정한다(임직원·계약직 → 확인 필요).
  - ‘계산→산정’은 검색어는 늘리지 않고 ‘함께 다룸’ 판정에만 쓴다.
- **결과:** 수치 요청 83건을 고치기 전과 비교했다. 달라진 결과는 모두 바르게 반영됐거나 추측하지 않고 멈춘 것이다.
