## 실행 환경

- 서버
  - Python 3.12 이상, 의존 패키지 9종(requirements.txt)
  - MCP 엔진용 quickjs는 Python 3.12까지만 설치, 3.13 이상은 Node.js로 대체
  - 별도 DB·미들웨어 불필요(파일 기반)
  - 검증 환경: 리눅스(Python 3.12·3.13)
- 브라우저: 최신 Chrome·Edge(검증: Chromium), PC·휴대폰 화면 모두 지원
- 사양
  - 서버 메모리: 내규 126건 진단 후 약 90MB, 모든 기능 사용 후 약 115MB(11/11 실측)
  - 일반 사무용 PC나 소형 서버 1대로 충분
- 네트워크
  - 외부망 없이 핵심 기능 모두 동작
  - 선택 사항: 법제처(law.go.kr) 상위법 최신성 확인, 알리오(alio.go.kr) 다른 기관 사례 조사, AI 제공자 수정안 작성

## 설치·실행 절차

1. 저장소 내려받기: git clone <프로젝트 주소> → cd <폴더>
2. 가상환경 만들기: python -m venv .venv → . .venv/bin/activate(Windows는 .venv\Scripts\activate)
3. 패키지 설치: pip install -r requirements.txt(실측 8~10초)
4. 서버 실행: python run_local.py(기동 1초 미만)
5. 브라우저로 http://localhost:5100 접속, 왼쪽 아래 “한국농업기술진흥원 · 등록 내규 126건” 표시 확인
6. (선택) 자동 시험: pip install pytest → python -m pytest -q tests(428건), node --test tests/js/*.test.mjs(91건)
  - quickjs와 Node.js가 모두 없으면 MCP 엔진 시험 7건은 건너뜀

## LLM 연결 설정

- 기본 동작: AI 없이 규칙 기반으로 처리
  - 수치·낱말 변경, 조 삭제·이동·신설
  - 조문 점검, 신구조문대비표, 개정문·개정문 검증, 부칙, 문서 11종
- 연결 위치: 화면 오른쪽 위 AI 단추(키 입력 전 [AI 미설정]) 또는 왼쪽 아래 [AI 설정]
  - 제공자(Gemini·Claude·GPT·사내·공통기반) 선택 → 키 입력 → 모델 선택 → 저장
  - 키는 브라우저 세션에만 저장(탭을 닫으면 삭제, 서버 저장 없음)
  - 기관 공용 키는 서버 환경변수로 지정 가능(GEMINI_API_KEY 등)
- 사내·공통기반 모델(OpenAI 호환): 행정안전부 AI 공통기반, 기관이 vLLM·Ollama로 운영하는 공개 모델(Gemma·GPT-OSS·EXAONE·Solar 등)
  1. 관리자가 서버 환경변수 OPENAI_COMPAT_BASE_URL에 모델 서버 주소 지정(예: http://llm.internal:8000/v1), 키가 필요하면 OPENAI_COMPAT_API_KEY도 지정
  2. 화면 [AI 설정] → 사내·공통기반 탭에서 모델 선택(서버가 모델 목록을 받아 표시)
  - 주소는 서버에서만 지정 → 개정안이 기관 밖으로 나가지 않아 공개 전 개정안에 적합
- 2종 모델 구동 확인
  - 같은 제정·개정 요청을 규칙 모드, OpenAI 호환 모델 2종, 다른 호환 서버, Ollama에서 코드 변경 없이 처리(자동 시험 tests/test_model_swap.py)
  - 실제 모델 2종(예: Gemini와 사내 Gemma) 구동·촬영 절차: docs/contest/모델교체시험.md
- 교체 방법
  - 같은 화면에서 제공자·모델만 변경(서버는 공통 호출 함수 하나로 처리)
  - 과부하 오류 시 같은 제공자의 대체 모델로 자동 전환
- MCP 서버 연결: MCP를 지원하는 AI 도우미가 도구 17개로 사용(docs/MCP.md)
  - 주요 도구: 에이전트 실행, 개정문·신구조문대비표·개정문 검증, 제정안 점검, 조문 점검, 건강검진, 다른 기관 사규(알리오) 찾기·읽기·수치 비교
  - 원격: 배포 주소의 /mcp를 claude.ai·ChatGPT 커넥터 등에 등록(설치 불필요)
  - 내 컴퓨터: python mcp_server/server.py를 Claude Desktop·Claude Code에 등록
  - 어떤 AI가 호출해도 같은 규칙 엔진이 결과 작성

## 기능 사용 순서

- ① 한 문장 개정
  1. 에이전트에 “여비규정 제15조의 일비를 3만원으로 올려줘” 입력 → 에이전트 실행
    - 별표 2 일비 열 25,000 → 30,000 반영(실측 0.4~0.5초)
    - 자료조사·인용 영향·점검·검토 보고서까지 14단계 진행
  2. 검토 보고서 열기
  3. 개정 화면 확인·검토 → 모두 점검하기(1초 미만, 대비표·인용 영향·형식 점검·개정문 검증 “일치”)
  4. 문서 받기 → 한글(hwpx) 또는 Word 저장
- ② 제정
  1. 제정 화면에서 내규명 “업무용 드론 운영지침” 입력
  2. (선택) 참고 자료 단계에서 위임 조항 추가: 법령명으로 조문 선택 또는 직접 입력(법령명·조항·내용, 법제처 미접속 망에서도 가능)
  3. 조문 초안 → 점검·검토 → 문서 받기(초안·점검·한글 문서까지 0.8초)
- ③ 정비·점검
  - 건강검진: 126건 전체 진단(약 1~1.5초, 서버 기동 후 첫 진단 약 3초), 오류 목록에서 없는 조문 인용·항 번호 오류 확인
  - 일괄 정비: “모든 내규에서 기획운영본부를 경영기획본부로 바꿔줘” → 25개 내규 35곳(별표·서식 6곳 포함) 변경, 개정문·부칙·통합 대비표 작성
  - 조 삭제: “여비규정 제20조를 삭제해줘” → 이 조를 인용하는 제24조도 수정 대상에 포함
- 시연영상: 위 흐름을 같은 순서로 녹화(외부망 연결 없이)

## 알려진 제약 사항

- 외부 조회: 법제처(상위법 최신성·조문)·알리오(다른 기관 사례)는 해당 사이트에 접속되는 망에서만 동작
  - 법제처 조회는 서버 환경변수 LAW_OC(법제처 Open API 아이디, open.law.go.kr 발급) 필요, 없으면 화면 안내 후 법제처 조회만 제외
  - 접속이 막히면 해당 조사만 빠지고 나머지는 그대로 동작
- AI 없이 되는 범위: 수치·낱말·조 단위 편집까지, 자유로운 문장 수정은 AI 연결 또는 화면에서 직접 수정
- 문서 형식
  - “제N조” 체계가 없는 매뉴얼형 문서는 조문 단위 개정 불가(화면 안내)
  - 구형 HWP는 본문 글자 위주로 변환 → HWPX 권장
  - 내려받은 HWPX는 한/글에서 최종 서식 확인 필요
- 데이터 전송: AI 사용 시 개정 의도·대상 조문이 선택한 AI 제공자에게 전송 → 공개 전 개정안은 사내 모델 사용 권장
- 재배포 제한 구성요소: 없음(패키지·글꼴별 판·라이선스는 THIRD_PARTY_LICENSES.md)
  - Python 패키지: BSD·MIT·Apache-2.0·PSF, certifi만 MPL-2.0(수정 없이 재배포 가능)
  - 화면 글꼴 Pretendard: SIL OFL 1.1, 저장소에 포함(assets/fonts/pretendard/, 라이선스 동봉) → 외부망 없이 같은 화면

## 개발 경위 요약

- 추진 배경
  - 기관별 규정 담당자는 1~2명이나 개정 한 건에도 할 일이 많음
    - 고칠 곳 찾기, 그 조를 인용한 다른 조·다른 규정 확인
    - 개정문 문형 맞추기, 신구조문대비표·개정 이유서·심의 서식 작성
  - 수작업이라 오류 발생: 운영 중인 내규 126건(조문 3,456개) 점검 결과 사람의 실수 6건 확인(없는·삭제된 조문 인용 3건, 항 번호 오류 3건)
  - 작업량 산정: 일비 한 줄 개정 약 2시간(다른 내규 전수 확인 시 약 4시간), 조직 명칭 일괄 변경 약 9.6시간 → 다른 내규 인용 확인은 현실적으로 생략
  - 업무망은 외부 AI 사용이 어려움 → AI 없이 처음부터 끝까지 동작하는 도구 필요
- 개발 과정
  1. 내규 데이터화: 내규 126건(HWPX·HWP·Word)을 조·항·호·별표·서식 단위로 구조화, 조문 간 인용 관계 연결
  2. 규칙 엔진: 개정문 문형(신설·삭제·이동 등), 조사 교정, 신구조문대비표, 부칙, 검토 보고서·심의안건서 등 문서 11종을 규칙으로 작성(한글·Word 저장)
  3. 자기 검증: 만든 개정문을 현행에 다시 적용해 수정안과 일치 여부를 매번 확인, 사람이 흔히 내는 오류 10종을 조문 점검으로 차단
  4. 에이전트: 한 문장 요청 → 자료조사·인용 영향·점검·심의 사전검토·검토 보고서·문서 세트까지 14단계 자동 진행
  5. 연결·확장: AI는 문장 다듬기용 선택 기능, 사내·공통기반·상용 모델을 코드 수정 없이 교체(5개 경로 시험), 법제처·알리오 조회, MCP 도구 17종 제공
  6. 확산성: 기관명·기관장·근거 규칙·절차를 설정 파일 하나로 분리, 가상 기관 내규 7건 도입 시험에서 설정 7개 항목만 변경(코드 수정 0줄)
- 성과(실측, 규칙 기반·외부망 없이)
  - 오류 주입 10종 1,243건 모두 적발(지적 위치 모두 정확)
  - 개정문 왕복 검증 619/619건 일치(조 신설·항 끼워 넣기·조 삭제·문장 추가·조 맞교환)
  - 처리 시간: 한 문장 요청 0.4~1.4초, 전체 내규 126건 진단 약 1초
  - 조직 명칭 일괄 변경(25개 내규 35곳): 수작업 약 9.6시간(산정치) → 도구 0.1초
  - 자동 시험 519건(Python 428건, 화면 엔진 91건) 모두 통과
- 기대 효과
  - 담당자는 문서 작성 대신 결과 확인에 집중, 다른 내규 인용까지 빠짐없이 확인
  - 다른 공공기관은 내규 원문 폴더와 설정 파일만 바꿔 같은 도구 사용 가능
