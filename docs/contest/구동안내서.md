> 이 문서는 양식 2-1 표 각 칸에 들어갈 내용의 원고다. 제출본(PDF)은 공고 양식(HWPX)에 kordoc으로 채워 만든다.
> 수치는 2026-11-04~06에 이 저장소에서 실제로 잰 값이다(「성과측정.md」·「다른기관_도입안내.md」·「시연영상.md」).
> 참가신청서(양식 1-1)의 개발물 개요(「참가신청서.md」)와 한 세트로, 두 문서의 모델 설명과 수치를 같게 맞췄다.
> 이 절차는 새 폴더에서 처음부터 그대로 따라 해 확인했다(「구동검증.md」, `scripts/contest_guide_check.js`).

## 실행 환경
- **서버**
  - Python 3.12 이상. 의존 패키지는 8종이고 `requirements.txt`에 있다.
  - 별도 DB·미들웨어가 필요 없다(파일 기반).
  - 검증 환경은 리눅스(Python 3.12·3.13)다.
- **브라우저:** 최신 Chrome·Edge(검증: Chromium). PC와 휴대폰 화면을 모두 지원한다.
- **사양:** 서버 메모리 사용량은 내규 126건을 진단한 뒤 약 71MB, 모든 기능을 차례로 쓴 뒤 약 114MB다. 일반 사무용 PC나 소형 서버 1대로 충분하다.
- **네트워크**
  - 외부망 없이 핵심 기능이 모두 동작한다.
  - 다음은 선택 사항이다. 법제처(law.go.kr)는 상위법 최신성 확인, 알리오(alio.go.kr)는 다른 기관 사례 조사, AI 제공자는 AI 수정안 작성에 쓴다.

## 설치·실행 절차
1. 공공 GitLab 저장소를 내려받는다: `git clone <프로젝트 주소>` → `cd <폴더>`
2. 가상환경을 만든다: `python -m venv .venv` → `. .venv/bin/activate`(Windows는 `.venv\Scripts\activate`)
3. 패키지를 설치한다: `pip install -r requirements.txt`(실측 8~10초)
4. 서버를 실행한다: `python run_local.py`(기동 1초 미만)
5. 브라우저로 `http://localhost:5100`에 접속한다. 왼쪽 아래에 “한국농업기술진흥원 · 등록 내규 126건”이 보이면 정상이다.
6. (선택) 자동 시험: `pip install pytest` → `python -m pytest -q tests`(402건), `node --test tests/js/*.test.mjs`(91건)

## LLM 연결 설정
- **기본은 AI 없이 동작한다(규칙 기반).** 다음은 AI 키 없이 처리한다.
  - 수치·낱말·조 삭제·조 이동·조 신설
  - 조문 점검, 신구조문대비표, 개정문과 개정문 검증, 부칙, 문서 11종
- **연결 위치:** 화면 오른쪽 위 AI 단추(키를 넣기 전에는 **[AI 미설정]**으로 보인다)나 왼쪽 아래 **[AI 설정]**을 누른다. 제공자(Gemini·Claude·GPT·**사내·공통기반**)를 고르고, 키를 넣고, 모델을 고른 뒤 **저장**한다.
  - 키는 브라우저 세션에만 저장되고 탭을 닫으면 지워진다. 서버에는 저장하지 않는다.
  - 기관 공용 키는 서버 환경변수로 둘 수 있다(`GEMINI_API_KEY` 등).
- **사내·공통기반 모델(OpenAI 호환):** 행정안전부 AI 공통기반이나 기관이 vLLM·Ollama로 띄운 공개 모델(Gemma·GPT-OSS·EXAONE·Solar 등)을 연결한다.
  1. 관리자가 서버 환경변수 `OPENAI_COMPAT_BASE_URL`에 모델 서버 주소를 넣는다(예: `http://llm.internal:8000/v1`). 키가 필요하면 `OPENAI_COMPAT_API_KEY`도 넣는다.
  2. 화면 [AI 설정]의 **사내·공통기반** 탭에서 모델 이름을 고르거나 적는다. 서버가 모델 서버의 목록을 받아 보여 준다.
  - 주소는 서버에서만 정하므로 화면에서 다른 곳으로 보낼 수 없다. 개정안이 기관 밖으로 나가지 않아 공개 전 개정안에 알맞다.
- **2종 모델 구동 확인:** 같은 제정·개정 요청이 규칙 모드, OpenAI 호환 모델 2종, 다른 호환 서버, Ollama에서 코드 변경 없이 도는 것을 자동 시험으로 확인했다(`tests/test_model_swap.py`). 실제 모델 2종(예: Gemini와 사내 Gemma)으로 구동·촬영하는 절차는 `docs/contest/모델교체시험.md`에 있다.
- **교체 방법**
  - 같은 화면에서 제공자와 모델만 바꾸면 된다. 서버는 공통 호출 함수 하나로 제공자를 바꿔 부른다.
  - 과부하 오류가 나면 같은 제공자의 대체 모델로 자동 전환한다.
- **MCP 서버로 연결:** MCP를 지원하는 AI 도우미(Claude Desktop·Claude Code 등)에 `python mcp_server/server.py`를 등록하면, 그 AI가 이 에이전트를 도구 11개로 쓴다. 에이전트 실행, 개정문·신구조문대비표·개정문 검증, 조문 점검, 건강검진 등이다. 어떤 AI가 부르든 결과는 같은 규칙 엔진이 만든다(`docs/MCP.md`).

## 모의데이터 안내
- **`samples/public_org/`(가상 공공기관 「가상행정진흥원」, 실제 기관 아님)**
  - 내규 7건(텍스트 6, Word 1)과 기관 설정 파일 `org_config.json`이 들어 있다.
  - 용도: 다른 기관 도입 시연
  - 투입 방법(Linux·macOS):
    ```
    export REG_DIR=po/regulations REG_MANIFEST=po/manifest.json ORG_CONFIG=samples/public_org/org_config.json
    python scripts/import_regulations.py samples/public_org/regs --reset
    python run_local.py
    ```
  - 투입 방법(Windows PowerShell):
    ```
    $env:REG_DIR="po\regulations"; $env:REG_MANIFEST="po\manifest.json"; $env:ORG_CONFIG="samples\public_org\org_config.json"
    python scripts\import_regulations.py samples\public_org\regs --reset
    python run_local.py
    ```
  - 들여오기는 0.07초 걸린다. 원본 폴더는 읽기만 하고, 결과는 별도 폴더(`po`)에 만든다.
  - 첫 줄(폴더 지정)이 빠진 채 실행해도 기본 내규 126건은 지워지지 않는다. 도구가 멈추고 안내한다. 기본 데이터로 돌아가려면 새 창에서 `python run_local.py`만 실행한다.
- **`samples/local_gov/`(가상 지자체 조례 2건):** 자치법규에도 같은 엔진이 도는지 보이는 예시다.
- **기본 데이터:** 한국농업기술진흥원 내규 126건(알리오 공시 공개본). 민감정보는 없다.

## 기능 사용 순서
- **① 한 문장 개정**
  1. 에이전트에 “여비규정 제15조의 일비를 3만원으로 올려줘”를 입력하고 **에이전트 실행**을 누른다.
     - 1초 안에(실측 0.6초) 별표 2 일비 열이 25,000에서 30,000으로 바뀐다. 자료조사·인용 영향·점검·검토 보고서까지 14단계가 진행된다.
  2. **검토 보고서 열기**를 누른다.
  3. 개정 화면의 **확인·검토**에서 **모두 점검하기**를 누른다(1초 미만, 대비표·인용 영향·형식 점검·개정문 검증 “일치”).
  4. **문서 받기**에서 **한글(hwpx)** 또는 Word를 받는다.
- **② 제정**
  1. 제정 화면에서 내규명 “업무용 드론 운영지침”을 입력한다.
  2. (선택) **참고 자료** 단계에서 위임 조항을 넣는다. 법령명을 입력해 조문을 고르거나, **직접 입력**을 눌러 나오는 입력칸에 법령명·조항·내용을 적고 **추가**를 누른다(법제처에 닿지 않는 망에서도 된다).
  3. 조문 초안 → 점검·검토 → 문서 받기 순서로 진행한다. 초안·점검·한글 문서까지 0.8초 걸린다.
- **③ 정비·점검**
  - **건강검진:** 126건 전체를 진단한다(약 1~1.5초, 서버를 켠 뒤 첫 진단은 약 3초). **오류 목록**을 누르면 전체 점검이 바로 돌아 없는 조문 인용이나 항 번호 오류를 보여 준다.
  - **일괄 정비:** 에이전트에 “모든 내규에서 기획운영본부를 경영기획본부로 바꿔줘”를 입력하면 25개 내규 35곳(별표·서식 6곳 포함)을 바꾸고 개정문·부칙·통합 대비표를 만든다.
  - **조 삭제:** “여비규정 제20조를 삭제해줘”를 입력하면 이 조를 인용하는 제24조도 수정 대상으로 담는다.
- 위 흐름은 시연영상에 같은 순서로 담았다(AI 키·외부망 없이 녹화).

## 알려진 제약 사항
- **외부 조회:** 법제처(상위법 최신성·조문)와 알리오(다른 기관 사례) 조회는 해당 사이트에 접속되는 망에서만 된다. 법제처 조회는 관리자가 서버 환경변수 `LAW_OC`(법제처 Open API 아이디, open.law.go.kr에서 발급)를 지정해야 하며, 없으면 화면에 안내가 나오고 법제처 조회만 빠진다. 막히면 그 조사만 빠지고 나머지는 그대로 동작한다.
- **AI 없이 되는 범위:** 수치·낱말·조 단위 편집까지다. 자유로운 문장 수정은 AI를 연결하거나 화면에서 직접 고친다.
- **문서 형식**
  - “제N조” 체계가 없는 매뉴얼형 문서는 조문 단위로 개정할 수 없다. 화면에 안내가 나온다.
  - 구형 HWP는 본문 글자 위주로 변환되므로 HWPX를 권장한다.
  - 내려받은 HWPX는 한/글에서 최종 서식을 확인한다.
- **데이터 전송:** AI를 쓰면 개정 의도와 대상 조문이 고른 AI 제공자에게 전송된다. 공개 전 개정안은 사내 모델 사용을 권장한다.
- **재배포가 제한되는 구성요소:** 없다. 패키지·글꼴별 판과 라이선스는 `THIRD_PARTY_LICENSES.md`에 정리했다.
  - Python 패키지는 BSD·MIT·Apache-2.0·PSF 라이선스다. certifi만 MPL-2.0이며, 수정 없이 재배포할 수 있다.
  - 화면 글꼴 Pretendard는 SIL OFL 1.1이다. 저장소에 포함했으므로(`assets/fonts/pretendard/`, 라이선스 동봉) 외부망 없이도 같은 화면이 나온다.

## 개발 경위 요약
- **문제 인식**
  - 기관마다 규정 담당자는 한두 명이다. 개정 한 건에도 할 일이 많다: 고칠 곳 찾기, 그 조를 인용한 다른 조·다른 규정 확인, 개정문 문형 맞추기, 신구조문대비표·이유서·심의 서식 작성.
  - 손으로 하다 보니 틀리기 쉽다. 실제로 운영 중인 내규 126건을 점검했더니 사람의 실수가 남아 있었다. 원문과 대조해 확인한 것만 6건이다(없는·삭제된 조문 인용 3건, 항 번호 오류 3건).
  - 다른 규정 126건을 일일이 열어 인용을 확인하는 일은 현실적으로 생략된다.
- **접근 방식**
  1. **AI 없이도 끝까지 가는 규칙 엔진.** 조문 구조 해석, 개정문 문형, 조사 교정, 인용 추적을 규칙으로 처리한다. 그래서 업무망에서 AI를 쓰지 못해도 동작한다. AI는 자유로운 문장 수정에 쓰는 선택 기능이고 모델을 바꿔 끼울 수 있다.
  2. **결과를 스스로 검증.** 만든 개정문을 현행에 다시 적용해 수정안과 같은지 매번 확인하고, 형식 점검으로 사람이 흔히 내는 오류를 막는다.
  3. **기관 설정 분리.** 기관명·기관장·근거 규칙·절차를 설정 파일 하나로 분리했다. 다른 기관은 내규 원문 폴더와 설정 파일만 바꾸면 쓸 수 있다(가상 기관 시험, 코드 수정 0줄).
- **성과**(실측, AI·외부망 없이)
  - 오류 10종을 1,243번 심어 모두 적발했다.
  - 개정문 검증은 619/619건 일치했다.
  - 한 문장 요청 처리는 0.4~1.4초다.
  - 조직 명칭 일괄 변경 작업은 수작업으로 약 9.6시간(산정치)이 걸리지만 도구로는 0.1초다.
