# MCP로 쓰기 — 규정 제·개정 에이전트를 AI 도우미의 “도구”로

규정 제·개정 에이전트를 **MCP(Model Context Protocol) 서버**로도 쓸 수 있다. MCP를 지원하는 AI 도우미에 연결하면, 그 AI가 대화 중에 이 에이전트의 기능을 직접 부른다. 연결 방법은 두 가지다.

| 연결 방식 | 이런 때 | 등록하는 것 |
|---|---|---|
| **원격(URL)** | claude.ai·ChatGPT 등 웹의 AI 도우미에서 쓸 때. 설치가 필요 없다 | 배포한 웹 서비스 주소 + `/mcp` |
| **내 컴퓨터(stdio)** | Claude Desktop·Claude Code 등이 이 저장소를 직접 띄울 때. 문서를 폴더에 파일로 저장한다 | `python mcp_server/server.py` |

**공통 특징**
- **같은 엔진:** 웹 화면과 같은 엔진·같은 내규 데이터를 쓴다. 개정문 문형, 신구조문대비표, 개정문 검증, 조문 점검이 화면과 똑같이 나온다.
- **모델 비종속:** 어떤 AI가 부르든 결과는 이 서버의 규칙 엔진이 만든다. AI는 요청을 이해하고 문장을 쓰는 역할만 한다.
- **다른 기관 사례(알리오):** 다른 공공기관이 알리오에 공시한 내부규정을 찾아 읽고, 수치를 견주고, 참고한 조문을 개정·제정 문서의 근거로 남긴다(4절).
- **읽기 위주:** 내규 원문은 읽기만 한다. 내규 등록·작업 실적 기록 같은 쓰기 기능은 넣지 않았다. 원격 연결은 파일을 쓰지 않는다. 내 컴퓨터 연결은 `output_dir`을 줬을 때 그 폴더에만 문서를 저장한다.

## 1. 원격(URL)으로 연결 — claude.ai·ChatGPT 커넥터

웹 서비스를 배포하면 같은 주소에 MCP 서버가 함께 열린다. **주소:** `https://<배포 주소>/mcp` (같은 것: `/api/mcp`)

**claude.ai(Claude 웹·앱)**
1. 설정 → 커넥터 → 사용자 지정 커넥터 추가
2. 이름(예: 규정 제·개정 에이전트)과 주소 `https://<배포 주소>/mcp`를 넣는다. 인증은 비워 둔다.
3. 대화창의 도구 메뉴에서 켠다.

**ChatGPT**
- 설정 → 앱·커넥터 → 고급에서 개발자 모드를 켠다 → 만들기에서 주소를 넣고 인증은 “없음”으로 둔다.
- 심층 리서치용 규격 도구(`search`·`fetch`)도 있다.

**Claude Code**
```
claude mcp add --transport http reg-agent https://<배포 주소>/mcp
```

**VS Code(`.vscode/mcp.json`)·Cursor 등**
```json
{ "servers": { "reg-agent": { "type": "http", "url": "https://<배포 주소>/mcp" } } }
```

**결과로 받는 것**
- 개정문·대비표·검증 결과는 글(JSON)로 받는다.
- 문서 세트(심의안건서·개정문·신구조문대비표·이유서 등)는 **내려받기 링크**(`download.hwpx`·`download.docx`)로 받는다. 서버에 저장하지 않고, 링크를 열 때 같은 요청을 다시 실행해 만든다.
- 조문 결과에는 원문 보기 링크(`url`)가 붙는다.

**환경변수(서버 관리자)**

| 변수 | 뜻 |
|---|---|
| `MCP_HTTP=off` | 원격 MCP를 끈다(기본 켜짐). |
| `MCP_TOKEN` | 값을 정하면 `Authorization: Bearer <값>` 머리글이 있어야 쓴다. 사내 배포용이다. 머리글을 넣을 수 있는 도구(Claude Code `--header`, VS Code, Cursor)에서 쓴다. 내려받기 링크는 이 값으로 서명된다. claude.ai·ChatGPT 커넥터는 이 방식의 토큰을 넣을 수 없으니, 공개 시연 서버는 비워 둔다. |
| `MCP_ALLOWED_ORIGINS` | 브라우저에서 직접 부르는 클라이언트의 출처(쉼표 구분). 화면 CORS 허용 출처(`ALLOWED_ORIGINS`, localhost)와 `MCP_PUBLIC_URL`은 늘 허용한다. 서버 간 호출(claude.ai·ChatGPT·Claude Code)은 출처가 없어 이 값과 상관없다. |
| `MCP_PUBLIC_URL` | 링크에 쓸 공개 주소. 프록시 뒤라 주소가 다르게 보일 때만 쓴다. |
| `MCP_PER_MIN` | 남용 방지: 같은 접속 주소(IP)에서 1분에 받는 호출 수(MCP 호출·문서 내려받기, 기본 120). 넘으면 429와 `Retry-After`. 인스턴스 메모리로 세므로 서버리스에서는 대략의 상한이다. |
| `MCP_TRUST_PROXY=1` | Vercel 밖에서 프록시 뒤에 둘 때만 `X-Forwarded-For`의 첫 주소를 접속 주소로 센다. 그 밖에서는 꾸밀 수 있는 머리글이라 믿지 않는다. |
| `MCP_ENGINE`, `MCP_ENGINE_TIMEOUT` | 엔진 실행 방식(`quickjs`·`node`, 6절)과 한 번의 제한 시간(초, 기본 90) |

**방식**
- MCP 2025-11-25·2025-06-18·2025-03-26 판의 Streamable HTTP를 따른다. 한 주소에 JSON-RPC를 POST하고, JSON으로 답한다(SSE만 받는 클라이언트에는 SSE 한 건).
- 세션을 두지 않는다. 요청마다 독립이라 서버리스(Vercel)에서도 된다. 서버가 먼저 보내는 알림 흐름(GET)은 없다(405).
- **막는 것**
  - 다른 웹사이트의 브라우저 호출: 허용 목록에 없는 Origin은 403이다. 요청의 Host와 같은지로는 판단하지 않는다(DNS 재바인딩 대비).
  - 지원하지 않는 판 머리글: 400
  - 1MB가 넘는 요청: 413
  - 엔진이 서버 API 밖(외부 주소, 내규 등록, 작업 실적 기록)을 부르는 것
  - 엔진에 가는 글의 길이: 내규안 3만 자, 고친 조문 합계 6만 자, 부칙·이유·목적 각 3천 자까지. 내려받기 링크도 같은 규칙으로 다시 정리한다.
- **응답 시간:** 원격에서 엔진 도구는 40초 안에 답한다. 다른 기관 수치 비교는 45초 안에 답하고, 그 안에 못 읽은 기관은 “시간 제한으로 건너뜀”으로 알린다. 흔한 클라이언트 요청 제한(60초) 안이다.

## 2. 내 컴퓨터(stdio)로 연결

```
python mcp_server/server.py
```

- **기관·데이터 위치:** 웹 서비스와 같은 환경변수를 따른다.
  - `ORG_CONFIG`, `REG_DIR`, `REG_MANIFEST`: 다른 기관 프로필과 내규 원문 위치
  - `LAW_OC`: 법제처 조회(상위법)
- **수동 실행은 필요 없다:** 아래처럼 AI 도우미에 등록하면 도우미가 직접 띄운다.

**Claude Desktop**: `claude_desktop_config.json`

```json
{
  "mcpServers": {
    "reg-agent": {
      "command": "python",
      "args": ["C:\\reg-agent\\mcp_server\\server.py"],
      "env": { "LAW_OC": "법제처 Open API 아이디" }
    }
  }
}
```

**Claude Code**

```
claude mcp add reg-agent -- python /경로/mcp_server/server.py
```

**그 밖의 MCP 클라이언트:** “표준 입출력(stdio)” 서버로, 명령 `python`, 인자 `mcp_server/server.py`의 전체 경로를 넣는다.

## 3. 도구(17개)

| 도구 | 하는 일 |
|---|---|
| `run_agent` | 한 문장 요청을 웹 화면의 에이전트와 똑같이 끝까지 처리한다. 개정·조 삭제·일괄 정비·제정·자문·상위법 영향, 그리고 “다른 기관은 재택근무를 어떻게 규정했어?”(다른 기관 사례)까지. 단계별 작업 내역과 결론, 개정이면 개정문·신구조문대비표·개정문 검증을 준다 |
| `amend_regulation` | AI가 고친 조문 전문을 받아 개정문, 신구조문대비표, 개정문 검증, 조문 점검, 심의 사전검토, 인용 영향을 돌려준다. 참고한 다른 기관 조문(`references`)을 근거로 남긴다 |
| `enact_regulation` | AI가 쓴 새 내규안을 받아 조문 점검·심의 사전검토와 제정 문서 세트를 만든다. 참고한 다른 기관 조문(`references`)을 근거로 남긴다 |
| `get_regulation` | 내규 조문 원문(전체 또는 고른 조)과 별표 |
| `search_regulations` · `list_regulations` | 낱말 검색(문장으로 물어도 됨), 내규 목록 |
| `check_regulation` | 내규 하나나 붙여 넣은 조문의 형식 점검(없는 조문 인용, 항·호 번호, 옛 명칭, 표기) |
| `health_check` | 기관 내규 전체 건강검진(점수·등급·문제가 많은 내규) |
| `citation_impact` | 고치거나 지울 조를 인용하는 조·내규·별표 |
| `upper_law_impact` | 상위법 개정 시 그 법을 인용하는 내규 조문 |
| `bulk_rename` | 모든 내규의 명칭 일괄 정비안(내규별 개정문, 별표·서식 포함) |
| `advise` | 내규 질의에 근거 조문 회신 |
| `alio_search_regulations` | **다른 기관 규정 찾기(알리오)**: 규정명으로 찾는다. 기본은 유관 기관이고, 같은 유형·전체·기관 지정도 된다 |
| `alio_get_regulation` | **다른 기관 규정 읽기**: 현행본 조문(관련 순 또는 고른 조), 목차, 알리오 원문 링크 |
| `alio_compare_values` | **다른 기관 수치 비교**: 같은 항목(일비 원·경조휴가 일 등)의 기관별 값·원문 문장, 최솟값·최댓값·중앙값과 우리 값 |
| `search` · `fetch` | ChatGPT 커넥터·심층 리서치 규격의 검색·원문 가져오기(`여비규정#제15조`, `여비규정#별표 2`) |

**쓰는 법**
- **요청을 바로 처리하기:** “여비규정 제15조의 일비를 3만원으로 올려줘”처럼 수치·낱말·조 삭제 요청은 `run_agent` 하나로 끝난다.
- **AI가 직접 고쳐 쓰기:** 자유로운 문장 수정은 AI가 `get_regulation`으로 현행 조문을 읽고 고쳐 쓴 뒤 `amend_regulation`에 넣는다. 그러면 개정문과 검증은 규칙 엔진이 맡는다.
- **검증 결과 알리기:** 개정문 검증(`verification.ok`)이 실패하거나 점검 오류가 나오면 AI가 사용자에게 그대로 알리도록 서버 안내문(instructions)에 적어 두었다.

## 4. 다른 기관 사례(알리오) 활용

알리오(공공기관 경영정보 공개시스템, alio.go.kr)에 공시된 다른 공공기관의 내부규정을 MCP로 가져와 제·개정에 쓴다. 웹 화면의 “다른 기관(알리오)”·“다른 기관은 얼마로 정했나”와 같은 조회다.

**흐름 예시 1 — 개정:** “우리 여비규정 일비를 다른 기관 수준에 맞춰 올리는 개정안 만들어줘”
1. `alio_compare_values`(item 일비, unit 원, keyword 여비): 유관 기관별 일비와 원문 문장, 중앙값
2. `get_regulation`(여비규정, 별표 2): 우리 현행 값
3. AI가 값을 정해 `amend_regulation`(별표 2 수정, `references`에 근거로 삼은 기관 조문)
4. 결과: 개정문·대비표·검증, 그리고 검토 보고서·심의 사전검토에 “다른 공공기관 운영 사례” 근거가 남는다. 문서 세트는 링크로 받는다.

**흐름 예시 2 — 제정:** “다른 기관 사례를 참고해 업무용 드론 운영지침 초안 만들어줘”
1. `alio_search_regulations`(keyword 드론) → `alio_get_regulation`(id, query 비행 승인)
2. AI가 여러 기관의 조 구성을 참고해 초안을 쓴다.
3. `enact_regulation`(title, text, `references`)으로 조문 점검·심의 사전검토·제정 문서 세트를 받는다.
- AI 없이 규칙만으로 하려면 `run_agent`(“업무용 드론 운영지침을 새로 만들어줘”)를 쓴다. 다른 기관의 같은 종류 규정을 찾아 조 구성을 초안 골격에 쓴다.

**흐름 예시 3 — 사례 조사:** `run_agent`(“다른 기관은 재택근무를 어떻게 규정했어?”)
- 결과 `compare`에 찾은 규정(`found`)과 열어 본 규정의 관련 조문(`opened`)이 온다.
- `id`를 `alio_get_regulation`에 넣으면 더 읽는다.

**주의**
- **기관 고르기:** `agencies`의 기관명은 정확히 맞거나, 일부만 적었으면 그 말이 든 기관이 하나뿐일 때만 고른다. 여럿이면(예: “한국전력” → 한국전력공사·한국전력거래소 …) 고르지 않고 후보를 알린다.
- **조회 실패:** 조회한 기관의 절반 이상이 실패하고 결과가 없으면 “그런 규정이 없다”로 읽히지 않게 오류로 알린다. 실패 수(`failed_count`)도 준다.
- **조회 범위:** 유관 기관은 `org_config.json`의 `alio.peer_depts`(주무부처)·`alio.peers`로 정한다. 범위가 넓으면 한 번에 48곳까지만 조회한다(알리오 서버 부담·응답 시간).
- **원문 형식:** 알리오 첨부 파일(한글·PDF·Word)의 글을 읽는다. 표로만 적힌 수치(별표 표)는 못 찾을 수 있다. 수치 비교는 원문 문장(`sentence`)을 보고 같은 기준인지 확인한다.
- **접속:** 서버가 alio.go.kr에 닿아야 한다.
  - 닿지 않으면 알리오 도구만 “연결하지 못했습니다”로 알리고, 나머지 도구는 그대로 된다.
  - 이 작업 환경(국외 클라우드)에서는 알리오가 연결을 끊었다. 그래서 Vercel 배포의 함수 지역을 서울(`vercel.json` `"regions": ["icn1"]`)로 정했다.

## 4-1. 범용 — 다른 기관 사규를 바로 개정·점검

배포 하나에 기관 하나를 등록해 쓰는 것이 기본이지만, 등록하지 않은 **다른 기관 사규**도 원문만 있으면 바로 다룹니다. 하나의 MCP 주소를 여러 기관이 함께 쓸 수 있습니다.

| 도구 | 범용 입력 | 하는 일 |
|---|---|---|
| `amend_regulation` | `source_text`(현행 원문 전체) 또는 `alio_id`(알리오 공시 규정) + `org` + `changes` | 그 원문을 현행으로 개정문·신구조문대비표·개정문 검증·조문 점검·같은 규정 안 인용 영향·문서 세트 |
| `check_regulation` | `text` 또는 `alio_id` + `org` | 그 규정만 점검(없는 조 인용·항 번호·표기·시행일) |
| `enact_regulation` | `org` + `title`·`text` | 그 기관 이름으로 제정 점검·문서 세트 |

- `org`: `{"org_name": "한국○○공단", "head": "이사장", "reg_word": "사규", "rules_name": "사규관리규정"}`. 개정문·대비표·검토 보고서·문서의 기관명·직위에 쓰입니다. `alio_id`면 알리오 기관명을 기본으로 씁니다.
- `org`나 원문을 주면 그 요청에서만 **이 서버에 등록된 내규와 대조하지 않습니다**. 등록 기관의 구 명칭·심의기준·작성 기준·근거 조항도 쓰지 않습니다. 동시에 들어온 다른 요청에는 번지지 않습니다(요청 머리 `X-RA-Ctx`).
- **흐름 예시**: “한국○○공단 여비규정 일비를 3만원으로 올리는 개정안 만들어줘”
  1. `alio_search_regulations`로 그 기관 여비규정을 찾는다.
  2. `alio_get_regulation`으로 고칠 조를 읽는다.
  3. AI가 고친 조문 전문을 쓴다.
  4. `amend_regulation(alio_id=…, changes=[…])`로 개정문·대비표·검증·문서 링크를 받는다.
- **알리오에 없는 규정**(지자체 조례 초안, 내부 검토본 등)은 원문을 `source_text`로 줍니다.
- **아직 등록 내규만 되는 것**: `run_agent`(한 문장 자동 수행), `health_check`, `bulk_rename`, `citation_impact`(다른 규정 사이 영향)는 기관 내규 전체가 필요해 등록 기관에서만 씁니다. 원문으로 받은 규정은 별표·서식 개정을 아직 지원하지 않습니다(조문만).
- **범용 MCP 전용 배포:** 같은 저장소를 `MCP_ONLY=1`로 한 번 더 배포하면 기관 내규 없이 위 범용 도구 6개만 여는 MCP 서버가 됩니다. 기관 웹 화면과 다른 주소를 쓰고, 주소를 브라우저로 열면 연결 안내가 나옵니다(README “범용 MCP 전용 배포”).
- 내려받기 링크: `alio_id`는 링크에 id만 담아 짧습니다. 긴 `source_text`는 주소 길이 제한으로 링크를 만들지 못할 수 있으니, 내 컴퓨터 연결의 `output_dir`로 파일을 받으세요.

## 6. 엔진 실행 방식

개정문·대비표·에이전트 도구는 웹 화면의 엔진(`assets/reg_agent.js`)을 그대로 돌린다. 두 가지 방식이 있고 결과는 같다(5절).

- **QuickJS(기본):** 파이썬 안에서 JS를 돌린다(`quickjs` 패키지, MIT). Node.js가 필요 없어 서버리스(Vercel)에서도 된다. Python 3.8~3.12는 `requirements.txt`로 함께 설치된다.
- **Node.js 18 이상(대체):** Python 3.13 이상처럼 `quickjs`의 미리 빌드된 판이 없으면 Node.js로 돌린다. `pip install quickjs`로 소스에서 빌드해도 된다(C 컴파일러 필요).
- **Vercel:** 함수에는 Node.js가 없다. 그래서 저장소의 `.python-version`으로 Python 3.12를 고정해 `quickjs`가 함께 설치되게 했다. 엔진이 없으면 엔진 도구만 이유와 할 일을 알리고, 나머지 도구는 그대로 된다.
- **바꾸기:** 환경변수 `MCP_ENGINE=quickjs` 또는 `node`. 기본은 QuickJS가 있으면 QuickJS다.
