# 규정 제·개정 에이전트 — 내규 제·개정 MCP

Claude·ChatGPT 같은 AI 도우미에 연결해 쓰는 **공공기관 규정 제·개정 MCP 서버**입니다. AI가 문안을 쓰면, 이 서버가 개정문·신구조문대비표·개정문 검증·조문 점검·제출 문서를 규칙대로 만듭니다. 같은 엔진으로 웹 화면도 제공합니다.

> 2026 공공 AI 대전환 챌린지 세션2 · 지정과제 ③ 출품작(한국농업기술진흥원)

**AI 혼자서는 틀리기 쉬운 일을 이 서버가 맡습니다.**

- **개정문 문형:** “제15조제1항 중 ‘2만원’을 ‘3만원’으로 한다.” 같은 개정문을 규칙으로 만듭니다.
- **개정문 검증:** 만든 개정문을 현행에 되돌려 적용해, 수정안과 같은지 기계적으로 확인합니다.
- **정합성:** 없는 조문 인용, 항·호 번호, 옛 명칭, 시행일, 그 조를 인용하는 다른 조를 찾습니다.
- **문서:** 심의안건서·개정문·신구조문대비표·이유서를 한글(hwpx)·Word(docx)로 만듭니다.

**어느 기관 사규든 쓸 수 있습니다.** 이 서버에 등록되지 않은 기관도, 알리오에 공시된 규정이나 붙여 넣은 원문만 있으면 그 기관 이름으로 개정·점검합니다([범용으로 쓰기](#범용으로-쓰기--다른-기관-사규)). 어떤 AI가 부르든 결과는 이 서버의 규칙 엔진이 만들기 때문에, 모델을 바꿔도 결과가 같습니다.

## 빠른 구동(3분)

### A. MCP로 연결하기 — 설치 없음

**1. 주소** — `https://<MCP 배포 주소>/mcp` (같은 주소: `/api/mcp`)

- 온라인 시연 주소(범용 MCP): **`https://reg-agent-mcp.vercel.app/mcp`** — 설치 없이 위 주소를 AI 도우미에 넣으면 됩니다. 브라우저로 열면 연결 안내가 나옵니다.
- 범용 MCP는 웹 화면과 **다른 주소**로 둡니다([범용 MCP 전용 배포](#범용-mcp-전용-배포)). 그 주소를 브라우저로 열면 연결 안내가 나옵니다. 기관 웹 화면 주소의 `/mcp`는 그 기관 내규까지 쓰는 MCP입니다.

**2. AI 도우미에 등록**

| 도우미 | 등록 방법 |
|---|---|
| claude.ai (웹·앱) | 설정 → 커넥터 → 사용자 지정 커넥터 추가 → 이름과 주소 입력(인증 비움) → 대화창 도구 메뉴에서 켬 |
| ChatGPT | 설정 → 앱·커넥터 → 고급에서 개발자 모드 켬 → 만들기 → 주소 입력, 인증 “없음” |
| Claude Code | `claude mcp add --transport http reg-agent https://<배포 주소>/mcp` |
| VS Code · Cursor | `.vscode/mcp.json`: `{ "servers": { "reg-agent": { "type": "http", "url": "https://<배포 주소>/mcp" } } }` |

**3. 첫 요청 3개** — 대화창에 그대로 적습니다.

| # | 요청 | AI가 쓰는 도구 | 받는 것 |
|---|---|---|---|
| ① | `여비규정 제15조의 일비를 3만원으로 올려줘` | `run_agent` | 별표 2 일비 25,000 → 30,000, 개정문, 신구조문대비표, 개정문 검증 “일치”, 문서 링크 |
| ② | `한국○○공사 여비규정을 알리오에서 찾아 일비를 3만원으로 올리는 개정안 만들어줘` | `alio_search_regulations` → `alio_get_regulation` → `amend_regulation(alio_id)` | 그 기관 이름으로 된 개정문·대비표·검증·문서 링크 |
| ③ | (다른 기관 규정 원문을 붙여 넣고) `이 규정 형식 점검해줘. 우리 기관은 ○○재단, 기관장은 이사장이야` | `check_regulation(text, org)` | 없는 조 인용·번호·시행일 등 그 규정만의 점검 결과 |

①은 이 배포에 등록된 한국농업기술진흥원 내규로 하는 예이고, ②·③은 어느 기관이든 됩니다. ②는 서버가 알리오에 접속되는 망에서만 됩니다.

### B. 내 컴퓨터에서 띄우기 — 웹 화면 + MCP

**1. 설치·실행** — Python 3.12 이상만 있으면 됩니다. DB·미들웨어가 필요 없습니다.

```bash
python -m venv .venv && . .venv/bin/activate        # Windows: python -m venv .venv  →  .venv\Scripts\activate
pip install -r requirements.txt
python run_local.py
```

**2. 접속** — 브라우저로 `http://localhost:5100`을 엽니다. 왼쪽 아래에 “한국농업기술진흥원 · 등록 내규 126건”이 보이면 정상입니다. MCP 주소는 `http://localhost:5100/mcp`입니다.

**3. 화면에서 해 볼 핵심 흐름 3개** — 각 1초 안팎입니다.

| # | 해 볼 일 | 결과 |
|---|---|---|
| ① 한 문장 개정 | **에이전트**에 `여비규정 제15조의 일비를 3만원으로 올려줘` → **에이전트 실행** | 별표 2 일비 25,000 → 30,000, 신구조문대비표, 개정문, 개정문 검증(“일치”), 검토 보고서, 한글 문서 |
| ② 제정 | **제정**에 내규명 `업무용 드론 운영지침` → **초안까지 한 번에** | 표준 조문 초안, 형식 점검, 문서 세트 |
| ③ 정비·점검 | **건강검진** → **오류 목록**. 또는 에이전트에 `기획운영본부를 경영기획본부로 모든 내규에서 바꿔줘` | 내규 126건 진단, 25개 내규 35곳 일괄 정비안(조사 교정·개정문·부칙) |

**4. 모의데이터로 다른 기관 도입 해 보기** — 가상 기관 「가상행정진흥원」 내규 7건으로 바꿔 띄웁니다. 결과는 `po/` 폴더에 만들고, 저장소 기본 데이터는 건드리지 않습니다.

```bash
export REG_DIR=po/regulations REG_MANIFEST=po/manifest.json ORG_CONFIG=samples/public_org/org_config.json
python scripts/import_regulations.py samples/public_org/regs --reset
python run_local.py
```

Windows PowerShell에서는 첫 줄을 `$env:REG_DIR="po\regulations"; $env:REG_MANIFEST="po\manifest.json"; $env:ORG_CONFIG="samples\public_org\org_config.json"`로 바꿉니다.

**5. Claude Desktop·Claude Code가 직접 띄우게 하기(stdio)** — 서버를 따로 켜 둘 필요가 없고, 문서를 폴더에 파일로 저장합니다.

```bash
claude mcp add reg-agent -- python /경로/mcp_server/server.py
```

Claude Desktop 설정 파일과 그 밖의 클라이언트는 [`docs/MCP.md`](docs/MCP.md) 2절에 있습니다.

**6. 자동 시험(선택)**

```bash

node --test tests/js/*.test.mjs      # 91건, Node.js 18 이상
```

## MCP 도구

도구는 17개입니다. **범용** 열은 이 서버에 등록되지 않은 다른 기관 사규에도 쓸 수 있는지를 뜻합니다.

| 묶음 | 도구 | 하는 일 | 범용 |
|---|---|---|---|
| 제·개정 | `amend_regulation` | 고친 조문 전문 → 개정문, 신구조문대비표, 개정문 검증, 조문 점검, 심의 사전검토, 인용 영향, 문서 | ✅ `source_text`·`alio_id`·`org` |
| | `enact_regulation` | 새 규정안 → 조문 점검, 심의 사전검토, 제정 문서 세트 | ✅ `org` |
| | `run_agent` | 한 문장 요청을 끝까지 처리(개정·조 삭제·일괄 정비·제정·자문·상위법 영향·다른 기관 사례) | 등록 내규 |
| 점검·진단 | `check_regulation` | 규정 하나의 형식 점검(없는 조 인용, 항·호 번호, 옛 명칭, 표기, 시행일) | ✅ `text`·`alio_id`·`org` |
| | `health_check` | 기관 내규 전체 건강검진(점수·등급·문제가 많은 내규) | 등록 내규 |
| | `citation_impact` | 고치거나 지울 조를 인용하는 조·내규·별표 | 등록 내규 |
| | `upper_law_impact` | 상위법 개정 시 그 법을 인용하는 내규 조문 | 등록 내규 |
| | `bulk_rename` | 바뀐 명칭을 모든 내규에서 조사까지 맞춰 바꾸는 정비안 | 등록 내규 |
| 찾기·읽기 | `search_regulations` · `list_regulations` · `get_regulation` | 등록 내규 검색·목록·조문 원문(별표 포함) | 등록 내규 |
| | `advise` | 내규 질의에 근거 조문 회신 | 등록 내규 |
| 다른 기관(알리오) | `alio_search_regulations` | 공공기관이 알리오에 공시한 규정 찾기(유관 기관·같은 유형·전체·기관 지정) | ✅ |
| | `alio_get_regulation` | 그 규정의 현행본 조문·목차·원문 링크 | ✅ |
| | `alio_compare_values` | 같은 항목(일비 원·경조휴가 일 등)의 기관별 값과 최솟값·중앙값·최댓값 | ✅ |
| 커넥터 규격 | `search` · `fetch` | ChatGPT 커넥터·심층 리서치 규격의 검색·원문(`여비규정#제15조`) | 등록 내규 |

**쓰는 법**

- **수치·낱말·조 삭제 요청:** 등록 내규면 `run_agent` 하나로 끝납니다.
- **자유로운 문장 수정:** AI가 현행 조문을 읽고(`get_regulation`·`alio_get_regulation`) 고친 전문을 `amend_regulation`에 넣습니다. 개정문과 검증은 서버가 맡습니다.
- **다른 기관 사례 참고:** `alio_*` 도구로 읽은 조문을 `amend_regulation`·`enact_regulation`의 `references`로 넘기면 검토 보고서와 심의 사전검토의 근거로 남습니다.

도구별 입력 형식은 [`docs/MCP.md`](docs/MCP.md) 3절에 있습니다.

## 범용으로 쓰기 — 다른 기관 사규

MCP 주소 하나를 여러 기관이 함께 씁니다. 규정을 미리 등록하지 않아도 됩니다.

**넣는 것**

| 입력 | 뜻 |
|---|---|
| `alio_id` | 알리오 공시 규정(`alio_search_regulations` 결과의 id). 서버가 공시 현행본 전문을 읽어 현행으로 씁니다. 기관명은 알리오 기관명을 기본으로 씁니다 |
| `source_text` (`check_regulation`은 `text`) | 알리오에 없는 규정(지자체 조례, 내부 검토본 등)의 현행 원문 전체(`제1조(목적) …` 형식) |
| `org` | 그 기관 이름: `org_name`(기관명), `org_short`(약칭), `head`(기관장 직위), `deputy`, `reg_word`(사규·내규·자치법규 등), `rules_name`(규정 관리 규정) |

**호출 예** — AI가 보내는 `amend_regulation` 입력:

```json
{
  "regulation": "출장규정",
  "source_text": "제1조(목적) 이 규정은 …\n제2조(일비) ① 일비는 1일 2만원으로 한다.\n② …",
  "org": { "org_name": "한국○○공단", "head": "이사장", "reg_word": "사규", "rules_name": "사규관리규정" },
  "changes": [ { "article": "제2조", "body": "① 일비는 1일 3만원으로 한다.\n② …" } ],
  "reason": "일비 현실화"
}
```

결과의 개정문은 “출장규정 일부를 다음과 같이 개정한다. / 제2조제1항 중 ‘2만원’을 ‘3만원’으로 한다.”이고, 문서에는 “한국○○공단”이 들어갑니다.

**섞이지 않게 막는 것**

- 이렇게 부른 요청에서는 이 서버에 등록된 기관의 내규·구 명칭·심의기준·작성 기준·근거 조항과 대조하지 않습니다. 예를 들어 다른 기관 규정의 “이사장”을 우리 기관의 구 명칭으로 짚지 않습니다.
- 기관 정보는 그 요청 하나에만 쓰이고, 동시에 들어온 다른 사람의 요청에는 번지지 않습니다.

**아직 등록 내규에서만 되는 것**

- `run_agent`, `health_check`, `bulk_rename`, 다른 규정 사이의 `citation_impact`: 기관 내규 전체가 있어야 합니다. 범용 개정에서 인용 영향은 같은 규정 안만 봅니다.
- 원문으로 받은 규정의 별표·서식 개정: 조문만 됩니다.
- 내려받기 링크: `alio_id`는 링크에 id만 담아 짧습니다. 아주 긴 `source_text`는 주소 길이 제한으로 링크를 만들지 못할 수 있으니, 내 컴퓨터 연결(stdio)의 `output_dir`로 파일을 받으세요.

자세한 내용은 [`docs/MCP.md`](docs/MCP.md) 4-1절에 있습니다.

## 대화 예시

**다른 기관 규정을 알리오 수준에 맞춰 개정**

> 한국○○공사 여비규정의 일비를 유관 기관 중앙값에 맞추는 개정안 만들어 줘.

1. `alio_search_regulations(keyword="여비", agencies=["한국○○공사"])`로 그 기관 여비규정을 찾습니다.
2. `alio_compare_values(item="일비", keyword="여비")`로 유관 기관 값과 중앙값을 봅니다.
3. `alio_get_regulation(id, articles=["제15조"])`로 고칠 조를 읽고, AI가 고친 전문을 씁니다.
4. `amend_regulation(alio_id=id, changes=[…], references=[…])`로 개정문·대비표·검증·문서 링크를 받습니다.

**붙여 넣은 규정 점검**

> (조례안 붙여 넣기) 이 조례안 형식 점검해 줘. 우리는 ○○시야.

`check_regulation(text=…, org={"org_name": "○○시", "reg_word": "자치법규"})`

**등록 내규 한 문장 처리**

> 모든 내규에서 기획운영본부를 경영기획본부로 바꿔 줘.

`run_agent(request=…)` — 25개 내규 35곳의 정비안과 내규별 개정문을 받습니다.

| `comparison_table` | 신구조문대비표(현행·개정안) |
| `verification` | 개정문 검증: `ok`가 `true`면 개정문을 현행에 적용한 결과가 수정안과 같습니다 |
| `check` · `review` | 조문 점검(오류·주의·표기 제안), 심의 사전검토 |
| `citation_impact` | 고친 조를 인용하는 조·내규·별표 |
| `download` | 원격 연결: 한글(`hwpx`)·Word(`docx`) 문서 세트 내려받기 링크. 서버에 저장하지 않고, 링크를 열 때 같은 요청을 다시 실행해 만듭니다 |
| `saved` | 내 컴퓨터 연결: `output_dir`에 저장한 파일 |

검증이 실패하거나(`verification.ok=false`) 점검 오류가 나오면 AI가 사용자에게 그대로 알리도록 서버 안내문에 적어 두었습니다.

## 보안과 운영

- **읽기 위주:** 규정 원문은 읽기만 합니다. 내규 등록·작업 실적 기록 같은 쓰기 기능은 MCP에 넣지 않았습니다. 원격 연결은 파일을 쓰지 않습니다.
- **서버에 남기지 않음:** 요청마다 독립(세션 없음)이고, 받은 원문·결과를 서버에 저장하지 않습니다. 서버리스(Vercel)에서도 됩니다.
- **모델 비종속:** 개정문·검증·점검·문서는 서버의 규칙 엔진이 만듭니다. 어떤 AI에 연결해도 결과가 같습니다.
- **전송 범위:** 사용자가 쓰는 AI 도우미에는 대화 내용과 도구 결과가 갑니다. 공개 전 개정안은 기관 보안지침에 맞는 AI 도우미에서 쓰세요.
- **막는 것:** 허용 목록에 없는 출처의 브라우저 호출(403), 1MB가 넘는 요청(413), 엔진이 서버 API 밖을 부르는 것. 입력 길이 상한도 둡니다(현행 원문 20만 자, 규정안 3만 자, 고친 조문 합계 6만 자).
- **응답 시간:** 원격에서 엔진 도구는 40초, 다른 기관 수치 비교는 45초 안에 답합니다(흔한 클라이언트 제한 60초 안).
- **남용 방지:** 같은 접속 주소(IP)에서 1분에 120번(`MCP_PER_MIN`)까지 받고, 넘으면 잠시 쉬라고 답합니다(429). 문서 내려받기 링크도 같이 셉니다. claude.ai·ChatGPT 커넥터는 그 회사 서버에서 부르므로 그 사용자들이 몇 개의 주소를 함께 쓴다는 점을 생각해 넉넉히 두었습니다. 서버리스는 인스턴스마다 따로 세므로 대략의 상한입니다. 호스팅 비용이 걱정되면 호스팅 쪽의 사용량 알림·지출 한도도 함께 두세요.

| 환경변수 | 뜻 |
|---|---|
| `MCP_TOKEN` | 값을 정하면 `Authorization: Bearer <값>`이 있어야 씁니다(사내 배포용). 내려받기 링크도 이 값으로 서명합니다. claude.ai·ChatGPT 커넥터는 이 방식의 토큰을 넣을 수 없으니, 공개 서버는 비워 둡니다 |
| `MCP_HTTP=off` | 원격 MCP를 끕니다(기본 켜짐) |
| `MCP_ALLOWED_ORIGINS` | 브라우저에서 직접 부르는 클라이언트의 출처(쉼표 구분) |
| `MCP_PUBLIC_URL` | 링크에 쓸 공개 주소(프록시 뒤라 주소가 다르게 보일 때) |
| `MCP_PER_MIN` | 같은 접속 주소(IP)에서 1분에 받는 호출 수(기본 120, 최소 10) |
| `MCP_TRUST_PROXY=1` | Vercel 밖에서 nginx 등 프록시 뒤에 둘 때만: `X-Forwarded-For`의 첫 주소를 접속 주소로 셉니다(Vercel은 따로 설정하지 않아도 됩니다) |
| `MCP_ENGINE`, `MCP_ENGINE_TIMEOUT` | 엔진 실행 방식(`quickjs`·`node`)과 한 번의 제한 시간(초, 기본 90) |

## 범용 MCP 전용 배포

같은 저장소를 **두 번** 배포합니다. 코드는 같고 환경변수 하나만 다릅니다.

| 배포 | 환경변수 | 주소를 열면 | MCP 도구 |
|---|---|---|---|
| 기관 웹 화면 (예: 한국농업기술진흥원) | (없음) | 그 기관의 웹 화면, 등록 내규 126건 | 17개(등록 내규 + 범용) |
| **범용 MCP** | `MCP_ONLY=1` | 연결 안내 화면(`/` → `/mcp`) | 6개: `amend_regulation`·`enact_regulation`·`check_regulation`·`alio_*` |

`MCP_ONLY=1`이면 이렇게 동작합니다.
- 이 저장소의 기관 프로필·내규를 싣지 않습니다. 기관명은 “○○기관”이고 등록 내규는 0건이며, 기관 이름은 요청마다 `org`로 받습니다.
- 등록 내규가 필요한 도구(`run_agent`·`health_check` 등)는 목록에서 빠지고, 불러도 쓸 수 없다고 답합니다.
- 내규 등록(`/upload` API)이 꺼집니다.
- 알리오 검색의 기본 범위가 ‘유관 기관’ 대신 전체 공공기관입니다(`agencies`로 기관을 고르면 그 기관만).
- 서버 안내문(instructions)도 범용 사용법으로 바뀝니다.

**Vercel에서 만드는 법**
1. Vercel → Add New → Project → 같은 저장소를 고릅니다.
2. 프로젝트 이름을 정합니다. 그 이름이 주소가 됩니다(예: `reg-agent-mcp` → `https://reg-agent-mcp.vercel.app/mcp`).
3. Environment Variables에 `MCP_ONLY` = `1`을 넣습니다. 알리오·문서 기능은 다른 값 없이 됩니다. 필요하면 `MCP_TOKEN`, `MCP_PUBLIC_URL`도 넣습니다.
4. Deploy 후 주소를 브라우저로 열어 “범용 규정 제·개정 에이전트 MCP” 안내가 보이면 정상입니다. 그 주소의 `/mcp`를 AI 도우미에 등록합니다.

내 컴퓨터에서 확인: `MCP_ONLY=1 python run_local.py` → `http://localhost:5100`

## 기관 전용으로 배포하기

범용 MCP만으로 부족하면(건강검진·한 문장 처리·일괄 정비를 우리 내규 전체에 쓰려면) 기관마다 배포를 하나 띄웁니다. 코드는 고치지 않습니다.

1. `org_config.json`을 복사해 기관명·직위·절차·심의기준을 고칩니다.
2. `python scripts/import_regulations.py <폴더> --reset`으로 규정 원문(HWPX·DOCX·HWP·PDF·텍스트)을 넣습니다.
3. (선택) `python scripts/build_embeddings.py`로 의미 검색 색인을 만듭니다.

- 지자체의 조례·규칙, 중앙부처의 훈령·예규·고시도 같은 엔진으로 다룹니다. 가상 지자체 예시는 `samples/local_gov/`에 있습니다.
- 단계별 안내는 [`docs/contest/다른기관_도입안내.md`](docs/contest/다른기관_도입안내.md)에 있습니다.

## 관리자 안내

**배포:** 사내 서버에서는 `python run_local.py`로 띄웁니다. 클라우드는 Vercel(`api/index.py`, `vercel.json`)을 씁니다. 배포하면 같은 주소에 웹 화면과 MCP(`/mcp`)가 함께 열립니다.

**환경변수(모두 선택)** — 전체 목록은 `.env.example`, MCP 관련은 위 [보안과 운영](#보안과-운영)에 있습니다.

| 이름 | 용도 |
|---|---|
| `GEMINI_API_KEY` 등 | 서버 공용 AI 키(웹 화면, 사용자 키가 우선) |
| `OPENAI_COMPAT_BASE_URL`, `OPENAI_COMPAT_API_KEY`, `OPENAI_COMPAT_MODELS` | 사내·공통기반 모델(OpenAI 호환)의 주소, 키(선택), 모델 목록(선택) |
| `LAW_OC` | 법제처 Open API 아이디. 없으면 상위법·행정규칙 조회만 꺼집니다 |
| `REG_UPLOAD_TOKEN` | 내규 등록 암호 |
| `GITHUB_TOKEN`, `GITHUB_REPO` | 읽기 전용 배포에서 내규 등록·작업 실적을 저장소에 커밋 |
| `LEDGER_ENABLED`, `LEDGER_DIR`, `LEDGER_BRANCH` | 작업 실적 기관 대장(기본 꺼짐)과 그 위치 |
| `ORG_CONFIG`, `REG_DIR`, `REG_MANIFEST` | 기관 프로필·규정 원문 위치 |
| `MCP_ONLY` | `1`이면 범용 MCP 전용 배포(기관 내규 없이 범용 도구 6개만, [위 절](#범용-mcp-전용-배포)) |

**내규 원문 등록**

- 웹: 왼쪽 메뉴 맨 아래 **내규 등록** 단추(`/upload`, 좁은 화면에서는 오른쪽 위 첫 아이콘)에서 HWPX·DOCX·HWP·PDF 등을 올립니다. 이름이 비슷한 기존 내규가 있으면 개정판인지 묻습니다.
- 일괄: `python scripts/import_regulations.py <폴더>`(`--reset`으로 새로 구성)

**알아 둘 점**

- 법제처(상위법)와 알리오(다른 기관 사례·`alio_id`) 조회는 그 사이트에 접속되는 망에서만 됩니다. 막히면 그 조사만 빠지고 나머지는 그대로 동작합니다.
- MCP의 개정문·에이전트 도구는 Python 3.12까지는 함께 설치되는 `quickjs`로 돌고, 3.13 이상에서는 Node.js 18 이상이 필요합니다. Vercel은 `.python-version`으로 3.12를 씁니다.
- 작성 중인 내용과 작업 실적은 기본으로 사용 중인 브라우저에만 남습니다. 기관 전체 대장은 `LEDGER_ENABLED=1`일 때만 남고, 본문·질의·검토자 이름은 보내지 않습니다.
